redraft

Edit the context, not the whole answer. Held tokens are reused, only the diverging span recomputes.

What you're watching

Ask most LLM setups to fix one typo in a long document and they regenerate the whole answer from scratch. redraft instead keeps the tokens of the old answer a fresh decode would still produce, and recomputes only the span the edit disturbed, inside the inference engine.

Below, two requests run against the same model on the same GPU: baseline (full regeneration) and redraft (reuse plus patch). A small edit, a typo fix, a reworded sentence, lets redraft finish well ahead of baseline. A large rewrite leaves little to reuse, so redraft can be slower than baseline. Both arms run every time, so you'll see that case too.

The idea follows incr: track dependencies, recompute only the delta. redraft applies that to the answer side of an LLM call, not just the prompt's KV cache.

Most real workloads involve many small, continuous re-derivations: a spreadsheet cell changes, a document field updates, an agent re-plans one step. This section replays that pattern over several steps and reports the cumulative time saved across the run.
